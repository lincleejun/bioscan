# ADR 0003：清理计划经人确认后把文件移到废纸篓（ADR 0001 “原片只读”的唯一例外）

日期：2026-10-26 · 状态：已采纳（owner 2026-10-26 决定） ·
依据：AfterShooting PRD v1（2026-10-26）§11、§13、AC15；契约修订 5E（`docs/gardener/contract.md`）

## 背景
- ADR 0001 规定 Gardener 永不在来源目录写入、移动、改名或删除。PRD §11 要求“清理以计划为单位”：用户先标记淘汰，
  再看计划（文件组、唯一物种影响、预计容量），确认后执行，并区分“可恢复移除”与“真正释放空间”。只读规则下这件事
  只能交给别的工具做，计划与执行之间的核对也就无从保证。
- 移到同一磁盘的废纸篓不产生空闲空间；永久删除无法撤销（PRD §11、§13）。

## 决定
1. **例外只此一处**：只有 `POST /cleanup-plans/{id}/run {confirm: true}` 会改动来源目录，动作只有一个：把计划里的文件
   移到 macOS 废纸篓（macOS 15+ 用 `/usr/bin/trash`，否则 Finder 的“移到废纸篓”）。Gardener 不做永久删除；清空废纸篓
   由人自己做。其余一切（扫描、标记、导出、Lightroom 交接）仍按 ADR 0001 只读。
2. **先计划后执行**：计划列出范围内淘汰的素材、每组全部文件（登记的 RAW/JPEG 等，加上旁边同名的 XMP/DOP/PP3
   sidecar）、字节数、同一拍摄的其他版本，以及“某物种最后的照片”。计划只读不改。
3. **执行前逐组重新核对**：仍为淘汰、文件集合不变（不多不少）、每个文件的大小与修改时间与计划一致；任何一项不符，
   整组不动并报告原因。原片离线或不存在的组跳过，绝不记为已删除。不是淘汰的素材的文件永远不动。
4. **如实报告容量**：结果分开给出“已移到废纸篓的字节（可恢复，未释放）”与“真正释放的字节”（本操作恒为 0）。
   每个文件的结果在移动后立即落库，中途失败或退出时记录仍然真实；再次执行只处理尚未移走的文件。
5. **记录不删**：素材、标记与历史行保留（契约 §10 X4），文件记为离线，素材 `meta.trashed` 记下计划与时间。
6. UI、CLI（`--yes`）与 MCP（`confirm: true`）走同一接口和同一核对，Agent 不能绕过。

## 后果
- CLAUDE.md 的产品决策里 ADR 0001 那一条注明此例外。
- 被移走照片的物种卡片计数暂未排除（PRD §11“不继续显示为当前有照片的物种”），留给身份单元。
- 受管理目录（导入单元）上线后，其副本作为 `asset_files` 登记即自动进入计划；对原位索引目录，界面明示“将修改来源目录”。
- 外置盘、网络卷上的废纸篓行为未在真实硬件上验证。
