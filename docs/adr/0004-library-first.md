# ADR 0004：Gardener 首先是图库，扫描归类是图库上的服务，导入是“有新照片时”的功能

日期：2026-11-13 · 状态：已采纳（owner 2026-11-13 决定，细节委托实现者敲定） ·
依据：owner 2026-11-13 的三条要求；PRD v0.1 §5、§9、§11；ADR 0001、0002

## 背景
- 现在的首页是「待整理」：一次拍摄走 扫描 → Review → 导入 三步，导入完成后界面没有去处，整理和日常找图是割裂的。
- 侧栏有六个并列概念（待整理、所有照片、本地目录、Collections、任务与导入、管理），中英混排，页面上常驻大段说明。
- 数据层已经是图库：素材不依赖任务或集合存在，可跨任务查询（PRD §9）；物种 Collection 跨任务派生（ADR 0002）；
  能力按任务开关，`meta` 一项不调用模型；`PATCH /tasks` 加能力后 `rescan` 可对已索引的素材补跑。缺的是界面。

## 决定
1. **什么都不做时，Gardener 是图库。** 首页是「图库」：全部照片按拍摄时间排列（可换排序），网格里只有缩略图、
   文件名和一行次要信息；状态徽标、筛选、快捷键说明不常驻。界面用语全部中文。
2. **两种进入方式，都不要求先填表。**
   - **添加文件夹**：就地索引，不复制、不移动、不改名（PRD §5 原有规则）。默认只开 `meta`（清点、时间、位置、预览），
     不跑模型，所以立刻可浏览。标题默认取文件夹名。
   - **从存储卡导入**：先扫描和 Review，再把留下的复制到用户选的目录（已有的导入计划）。只有这条路复制文件。
3. **归类是用户按需打开的服务**，不是进入图库的前提：物种、人物、连拍、质量与美学，对一个文件夹或一次拍摄开启后补跑。
   结果以“看图库的方式”出现：物种、人物；时间和文件夹不需要模型。
4. **侧栏只留用户已经认识的名词**：图库、文件夹（已索引来源在磁盘上的真实目录，并入原「本地目录」）、物种、集合；
   「待整理」只在有未整理的批次时出现；任务列表并入「管理」。不做用户自建的虚拟文件夹树：手动分组用集合。
5. **文件归属**：Gardener 只索引。导入之后不再移动或改名文件；Lightroom 是可选出口，由用户决定是否使用。
6. **地点**暂不作为一种视图：现在只有 GPS 坐标，没有离线地名。有了地名来源再加。
7. 回忆、推荐、时间线，以及让 agent 通过 MCP 找素材，都是图库之上的二次应用，建立在同一套查询（契约 §6.4）上。

## 分步
1. 图库页与侧栏精简（只改界面，不改数据与接口）。
2. 「添加文件夹」一步到位（`meta` 预设、文件夹选择器），导入完成后落在图库里的这次拍摄。
3. 文件夹视图读已索引的来源；按需开启归类的入口。
4. README、About、视频改为“图库 + 自动归类”的定位。

## 后果
- 「任务」从主导航退到管理里，仍是扫描执行的记录单位；契约里的任务接口不变。
- PRD §11 的主导航表由本决定第 4 条取代。
