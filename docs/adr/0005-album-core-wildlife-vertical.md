# ADR 0005：Gardener 是拍野生动物的人的相册

日期：2026-11-13 · 状态：已采纳（owner 2026-11-13 两轮讨论后决定） ·
依据：2026-11-13 的产品评审（开源图库、选片与拍鸟工具的官方文档；一次只凭 README 的首次安装实测）；ADR 0001–0004

## 一句话
Gardener 是拍野生动物的人的相册：浏览、扫描入库、筛选、分类自动完成；野生动物这个分类要做到最好；
相册的能力同时开放给 coding agent。

## 决定
1. **相册是基础和核心，任何时候都要稳。** 可检查的规则：不加载任何模型时，浏览、加入文件夹、标记、垃圾箱、集合、
   导出都能用；模型、名录或分析失败只影响“归类结果”，不影响这几件事。新功能不得破坏这条。
2. **够用，不做成 Immich。** 明确不做：手机备份、多用户与权限、对外分享链接、云同步。
   人物分组已有，作为日常能力保留。
3. **找得到比管得多重要。** 标签和搜索是相册的日常：标签搜索、内容搜索（场景、物种、文件名、时间地点）先做齐，
   语义搜索（用一句话找图）随后补。
4. **面向拍野生动物的人，并在这个方向深度优化。** 其他照片也能放、也好用，但不为它们单独优化。
   「鸟类识别」升级为「野生动物」分类：鸟类、哺乳类、其他动物同一套流程，对外用语一致。
   这是高频高能的部分：识别到物种、连拍归并、挑出好片、标出废片、按物种长期积累。
5. **直接竞品是 Project Kestrel 和慧眼选鸟（SuperPicky）。** 学它们的产品做法，不取它们的代码和模型权重
   （GPL-3.0 / AGPL-3.0；其中一个鸟种模型是非商用许可）。导入测试时用同一批照片的副本同时跑这两款，记录差距。
   通用图库（Immich 等）和婚礼选片工具不是对标对象。
6. **默认流程兑现承诺。** 「加入并自动归类」默认就是完整的野生动物流程（识别物种、连拍、好片与垃圾箱）；
   「加入图库」保持不跑模型。界面上说做了的事，必须真的做了。
7. **形态是服务 + 网页。** 服务可以放进 Docker 运行，网页通过 API 连它；以后能部署到别处。
   桌面 App 等功能好用之后再做，现在不做。
8. **AI native（加分项）：Gardener 只负责让 agent 能找、能加、能分类、能挑。** 经 MCP 和 CLI 开放同一个服务。
   成片、发布到社交媒体由 agent 在外部完成，Gardener 不内置。

## 现状与差距（只列差距，2026-11-13）
- 物种覆盖不是差距：鸟类名录 11,172 种（AviList 全表）、哺乳类 6,903 种（MDD）、其他动物 366,460 种，
  与两款竞品的鸟种数相当，其他类群更多。
- 安装：10 步、终端、10 GB 以上下载、两份名录手工获取；竞品是一个 App。
- 搜索：`q` 只匹配文件名；标签与场景只能当筛选条件用，没有统一的搜索框；没有语义搜索（SigLIP2 向量已有）。
- 物种没有随附的中文名；界面只有中文，README 是英文。
- 好片的排序区分度弱；连拍、选片在真实拍摄上的效果没有量过；没有和两款竞品在同一批照片上比过。
- MCP 已有 34 个工具（建任务、查询、标记、集合、物种、导入、清理、Lightroom）；缺：搜索（同上）、
  给照片加标签、按路径加入文件夹的一步工具。

## 顺序
1. 修评审里的六类缺陷（issue #177 逐条列出通过条件）。
2. 搜索框：标签 + 内容 + 物种 + 文件名；然后语义搜索。
3. 野生动物做深：好片质量、与两款竞品对比后的改进。
4. agent：补齐 MCP 缺口，写一份 agent 使用说明。
