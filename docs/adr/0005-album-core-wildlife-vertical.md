# ADR 0005：Gardener 是相册；野生动物是它做得最深的一个分类；一切都能由 agent 驱动

日期：2026-11-13 · 状态：已采纳（owner 2026-11-13 决定） ·
依据：2026-11-13 的产品评审（开源图库、选片与拍鸟工具的官方文档；一次只凭 README 的首次安装实测）；ADR 0001–0004

## 一句话
Gardener 是一个本地相册：浏览、扫描入库、筛选、分类自动完成；野生动物是这个相册里做得最深的垂直分类；
相册的全部能力同时开放给 coding agent。

## 决定
1. **相册是基础和核心，任何时候都要稳。** 可检查的规则：不加载任何模型时，浏览、加入文件夹、标记、垃圾箱、集合、
   导出都能用；模型、名录或分析失败只影响“归类结果”，不影响这几件事。新功能不得破坏这条。
2. **够用，不做成 Immich。** 明确不做：手机备份、多用户与权限、对外分享链接、云同步、服务器部署。
   人物分组已有，保持现状，不扩展。
3. **找得到比管得多重要。** 标签、搜索是相册的日常：标签搜索、内容搜索（场景、物种、文件名、时间地点）先做齐，
   语义搜索（用一句话找图）随后补。
4. **「鸟类识别」升级为「野生动物」分类。** 对外用语、侧栏、README 都说野生动物：鸟类、哺乳类、其他动物同一套流程。
   这是高频高能的部分：识别到物种、连拍归并、挑出好片、标出废片、按物种长期积累。
5. **直接竞品是 Project Kestrel 和慧眼选鸟（SuperPicky）。** 学它们的产品做法，不取它们的代码和模型权重
   （GPL-3.0 / AGPL-3.0；其中一个鸟种模型是非商用许可）。通用图库（Immich 等）和婚礼选片工具不是对标对象。
6. **默认流程兑现承诺。** 「加入并自动归类」默认就是完整的野生动物流程（识别物种、连拍、好片与垃圾箱）；
   「加入图库」保持不跑模型。界面上说做了的事，必须真的做了。
7. **AI native（加分项）：agent 能做人在界面上能做的每一件事。** 同一个本地服务，经 MCP 和 CLI 开放：
   搜索与查找、加入与扫描、分类、标记、集合、导出。挑素材、配合成片 skill、发布到社交媒体由 agent 在服务之外完成；
   Gardener 不内置发布，对外发布每次都要人确认。

## 现状与差距（只列差距，2026-11-13）
- 物种覆盖不是差距：鸟类名录 11,172 种（AviList 全表）、哺乳类 6,903 种（MDD）、其他动物 366,460 种，
  与两款竞品的鸟种数相当，其他类群更多。评审里“对手覆盖更广”的说法是错的。
- 安装：10 步、终端、10 GB 以上下载、两份名录手工获取；竞品是一个 App。
- 搜索：`q` 只匹配文件名；标签与场景只能当筛选条件用，没有一个统一的搜索框；没有语义搜索（SigLIP2 向量已有）。
- 物种没有随附的中文名；界面只有中文，README 是英文。
- 好片的排序区分度弱；连拍、选片在真实拍摄上的效果没有量过；没有和两款竞品在同一批照片上比过。
- MCP 已有 34 个工具（建任务、查询、标记、集合、物种、导入、清理、Lightroom）；缺：搜索（同上）、
  给照片加标签、按路径加入文件夹的一步工具。

## 顺序
1. 修评审里的缺陷（默认不识别物种、打开清理计划就改标记、轮询 400、几处说法不一致、安装文档）。
2. 对外说法与产品一致：README、GitHub About、侧栏用语。
3. 搜索框：标签 + 内容 + 物种 + 文件名；然后语义搜索。
4. 安装：一条命令取齐名录；再决定是否打包成 App。
5. 野生动物做深：中文物种名、好片质量、在同一批照片上对比两款竞品。
6. agent：补齐 MCP 缺口，写一份 agent 使用说明。
