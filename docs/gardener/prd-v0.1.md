# Gardener PRD v0.1

状态：已确认产品方向与核心行为的汇总稿，作为原型和技术方案输入；不代表产品已实现或实验已通过。依据为本次讨论的 D01–D37，逐项来源见 [项目上下文与决策](00-项目上下文与决策.md)。本文件是当前产品基线；早期研究与目录草案用于背景查证，冲突时以最新明确决策为准。

## 1 产品定位与价值

Gardener 是 local-first、开源的 PC 摄影工作台。首版以拍摄归来后的整理与 Review 为重心，同时保存持续可查询的素材记录。初始关注旅行与野生动物混合拍摄，帮助用户识别、分类、辅助选择、人工确认、组织并输出。

完整保留候选与减少审阅遗漏是核心要求。美学不佳但有记录意义的照片仍能被找到并选择。Coverage Review 是重要能力，其市场差异化仍需实测，不能当作已证明的独占优势。

## 2 场景与交付结果

典型输入为多张 SD 卡或目录、约 500GB、5000 张 RAW/JPEG 与 100 个视频。文件数、逻辑素材数和字节量需区分，RAW/JPEG 的身份与显示配对规则待技术方案明确。

一次整理交付三类结果：完整拍摄记录；人工确认的精选集合；可按需交给后期的输出。未选素材仍可查询，用户以后可继续 Review 和改判。Review 完成不强制复制或导出，不以“必须选出 300 张”为成功条件。

## 3 首版范围

首版覆盖任务接入、快速预览、后台分析、Collections、人工 Review、组合查询、XML 导出、能力与标签管理，以及持久化和任务恢复。

视频以整段素材管理。自然语言/Embedding 检索、相似图搜索、自动精彩片段、视频裁切拼接、声音识别、主题作品集展示留待后续。已有向量能力仍可用于当前连拍/相似分组。首版不做永久删除原片、插件市场或复杂流程编排。

首个平台与格式支持矩阵尚未冻结。采用 C/S 架构，UI、CLI、MCP 共用后台服务与管理能力；CLI/MCP 首版接口交付范围尚未确定。

## 4 核心概念与规则

| 概念 | 产品语义 |
|---|---|
| 任务 | 一次 Import/Scan 工作，可有多个来源及后续追加，包含背景和配置 |
| 素材 | 用户浏览与判断的对象，关联原文件及其位置，不依赖某个 Collection 才存在 |
| Collection | 内容组织和 Review 单位；一个任务可产生一个或多个集合，素材可属于多个集合 |
| Manual Collection | 显式维护成员，可改名、描述、调整成员、合并或拆分 |
| Smart Collection | 保存查询规则，按规则获取成员；当前结果可另存为 Manual |
| Flag / Star | 人工选择状态与星级，随素材全局共享，彼此独立 |
| AI 建议 | 机器产生的推荐、拒绝、排序及理由，与人工判断分开保存 |
| Review 状态 | 区分素材判断与集合完成；集合完成进度独立 |

同一素材在不同集合中的人工 Flag/Star 一致。从集合移除不改变 Flag，不移动或删除原片。机器重跑不覆盖人工选择或集合整理。

## 5 接入与渐进预览

接入页面选择一个或多个目录，支持标题、副标题、描述等背景信息，不要求先创建 Collection。标题等字段是否必填、按钮命名与默认值在原型中细化。Import 这个名字不应暗示已复制文件；扫描不强制复制全部原片。

主流程：创建任务 → 发现素材并生成预览 → 后台逐项分析 → 渐进产生 Collections → 分组 Review → 按需导出。

Preview 优先从 RAW 提取 thumb，允许用户先浏览和标记，详细分析在后台服务运行。页面持续更新预览和分析状态，已就绪素材不等待全任务完成。失败不应移除已可浏览条目，未启用、待运行、失败和未识别结果分别表达。

浏览稳定性为要求：新结果不突然打乱当前正在看的图片与选中项。缩略图提取失败的回退策略、详细分析所用分辨率与更新机制待技术方案明确；低分辨率 thumb 不能被当作完整 RAW 解码或精细对焦的验证。

任务可暂停继续、停止并保留已有结果、中断后恢复、单项失败重试。来源离线时保留记录和已有预览，重新连接核对来源后继续。结束汇总发现量、完成量、失败项和未运行能力，分析完成不等于 Review 完成。

### 多任务与执行状态

用户新增明确需求（D35）：可多次创建独立扫描任务处理不同内容；每次扫描完成即结束该次执行，不等待人工 Review。用户可切换其他任务，之后再返回旧结果审阅。

任务至少分开表示扫描执行状态和 Review 进度。列表可以同时显示“扫描完成 / 未审”和“扫描中 / 已审部分”。人工审阅不占用扫描执行名额，也不能阻止下一任务开始。扫描成功、部分失败、失败或取消各自如实报告，不统一冒称完成。

首版范围已确认：支持创建多个独立任务、任务列表、后台扫描队列、任务切换和历史结果续审；默认逐个执行重型扫描，一个扫描结束后继续排队任务。用户 Review 任务 A 时可后台扫描任务 B。多任务同时进行重型 AI 推理后置；具体资源调度和队列异常处理仍待技术方案细化。

已有追加来源/重分析需求继续保留。追加或重分析记录新一轮执行，不改写过去扫描历史；不同拍摄内容可新建独立任务。实现上建议区分长期任务与每次扫描运行，并保存配置和输入范围快照。具体数据结构、排队任务配置修改、来源离线时跳过策略仍待技术方案细化。

## 6 扫描能力与产出

以下是已暂认可的组织方式，具体实现与支持范围须验证。

| 能力 | 主要产出 |
|---|---|
| 基础清点与元数据 | 文件信息、拍摄时间、设备、位置、预览与读取状态 |
| 内容识别分类 | 内容标签及对应分组 |
| 地点与事件 | 基于已有信息的拍摄分组建议 |
| 物种识别 | 物种候选及不确定性信息 |
| 连拍与相似画面 | 比较组、推荐帧，保留全部候选 |
| 质量分析 | 模糊、对焦、曝光等风险和依据 |
| 美学与选择建议 | 排序、AI Pick/Reject 建议及可提供的依据 |

逐素材结果与来源持久保存，由 Collection 和筛选呈现。用户描述是背景，不能静默变成每张图的精确 GPS 或确认物种。机器不能提供可靠解释时如实表示，不编造原因。

## 7 能力 标签与扫描配置管理

能力、标签体系、扫描配置分别管理。能力不直接绑定某个模型；运行保存能力/模型版本和参数。标签使用稳定身份，支持别名和层级；改名、合并、拆分、停用保留历史，人工确认与机器建议分开。

升级流程：小批素材试跑新版本 → 比较新旧结果 → 设置后续任务默认版本 → 按需重分析旧素材。不自动全量重跑；影响 Smart Collection 时先展示变化，不静默改变已审范围。

| 扫描预设 | 能力组合 |
|---|---|
| 快速整理 | 基础预览、元数据、内容分类、时间分组 |
| 摄影筛选 | 增加连拍/相似、质量、美学与选择建议 |
| 野生动物 | 在摄影筛选基础上增加主体检测和物种识别 |

用户可修改另存预设，任务保存启动时配置快照。能力依赖由技术方案明确。

运行模式独立为安静、均衡（默认）、全速。模式只控制资源，不静默关闭能力或降低分析质量；当前大图与可见预览优先，允许暂停分析继续 Review。资源上限和调度方式待验证。

## 8 Collection Review 与覆盖检查

结果页以地点、事件、场景、物种等内容 Collections 为主要 blocks；AI Pick/Reject、未审、人工 Pick 是快捷视图或组内筛选，也可保存为 Smart Collection。具体 block 摘要字段、层级和默认排序尚待原型确定。

Review 页面含集合信息与筛选、缩略图网格、详情和操作区；支持连拍折叠、大图、主体放大、并排比较、批量 Flag/Star 与撤销。详情独立显示 AI 信息和人工判断。动作自动留痕，人工主观理由可选，不强迫每张填写说明。

整组低分也必须可见，用户可选任意多张或明确零选。Coverage 提醒未覆盖地点/事件/物种，不强制每组保留一张。对于根本没有扫描素材的地点，需要额外行程证据才能判断缺失，不宣称系统能凭空知道所有到访地点。

完成规则：

- 滚动经过不算素材已审；明确判断的具体操作在原型中细化。
- “完成本组”由用户主动触发，不要求每张打 Flag/Star；显示未逐张处理数量，未标记项保持原状态，不自动 Reject。
- “本组不留”明确零选；遇到已有全局 Pick 时显式处理冲突，不能静默批量改判。
- 离开可续审，完成可进入下一组；新增成员标记新增待审并保留历史完成记录。
- 各集合进度独立；任务级完成范围与重叠集合计数仍需明确。

新增来源复用有效结果、处理新增变化项；补开能力仅补跑相关分析。新分组作为建议，保留人工改名、拆分和成员调整。

## 9 查询与视频

任务/Collections 用于回到某次拍摄；全部素材用于跨任务查询。支持组合筛选时间、地点、内容/物种、Flag/Star、AI 建议、审阅状态、任务/集合/来源、媒体类型、原片在线状态和分析状态。结果可继续 Review，规则可保存 Smart Collection。离线时可查记录与已有预览，没有预览时不伪装原片可用。

视频按整段进入同一体系，读取可用时长、时间、分辨率、封面，支持可用格式播放、拖动、人工 Flag/Star。无法播放仍保留条目并可外部打开。具体容器与编码支持按真实样本验收，不承诺任意视频均可播放。

## 10 输出与后期交接

导出提供“复制内容”开关，默认关闭：关闭时只生成一个 XML，开启时复制所选素材；视频复制整段原文件。

XML 的建议内容是原片定位、Collection、标记、AI 建议和 Review 结果，开启复制时引用导出位置。具体 schema、路径可移植性、包含历史的深度、重新导入及文件命名尚未冻结。

Lightroom/XMP 仍是交接目标，但单一 Gardener XML 不等于逐照片 XMP，也不意味着 Lightroom 能直接读取。需另定兼容出口并用实际版本和格式往返验证。导出范围、跨集合去重和副本校验/同名冲突规则亦须在实施前明确。

## 11 页面结构

| 主导航 | 内容 |
|---|---|
| 全部素材 | 跨任务查询与 Smart Collection |
| Collections | 内容 blocks、集合整理和分组 Review |
| 任务 | 创建、进度、Preview、追加来源、暂停恢复和重试 |
| 管理 | 能力/版本、标签、预设、运行模式、数据和缓存位置 |

同一任务内有 Preview 与 Collections 两个主要视图，共享素材与人工标记，可随时切换，任务进度持续可见。导出位于 Collection 或筛选结果操作中，不单列为主导航。

## 12 服务架构、存储与可靠性

已确认（D37）：采用 C/S 架构，UI、CLI 与 MCP 都通过同一后台服务访问素材、任务、Collections、Review 和管理能力。local-first 指默认服务、原片索引、数据库和缓存位于用户电脑；不等于业务逻辑只能存在于 UI。

以下是技术方案建议，具体协议与部署方式待定：

- 后台服务统一拥有业务规则与持久化写入；客户端不直接修改 SQLite、任务状态或缓存索引。人工 Flag/Star、AI 建议与历史由服务分别保存。
- 扫描任务提交后返回任务标识，由后台队列与工作进程执行；关闭页面、CLI 退出或 MCP 连接断开不取消扫描。后台服务自身退出后的恢复策略另行定义。
- UI 通过查询和进度事件展示渐进预览；CLI/MCP 调用相同应用能力，避免各自实现一套扫描与管理逻辑。
- 预览文件独立存放，由服务按素材标识提供访问；扫描路径指服务所在电脑的路径。手机选择的路径不能直接当作服务器目录。
- 首版可采用单个服务加后台工作进程，保持 SQLite 单一写入边界；多客户端修改通过记录版本检测冲突，不静默覆盖人工判断。
- 本机访问为默认；若开放局域网，则需定义认证、来源目录权限与预览访问范围。当前局域网 HTML 原型不等于正式服务已实现。

协议、服务生命周期、任务恢复、接口版本和多客户端冲突契约作为下一轮技术设计重点。


SQLite 保存整理记录，本地独立目录保存预览缓存。建议数据库保存预览索引而非图片本体；具体表结构、迁移和缓存索引由技术方案定义。原片保留原有位置，不自动移动、改名、删除。

已确认清理边界：

| 操作 | 行为 |
|---|---|
| 归档任务 | 从日常列表收起，素材、集合与历史仍可查询 |
| 删除 Collection | 仅删除集合及成员关系，保留素材和全局 Flag/Star，支持恢复 |
| 清理缓存 | 只释放缓存空间，保留整理记录；原片可用时重建 |
| Reject | 仅改变选择判断，不触发文件移动或删除 |

首版不提供永久删除原片。Collection 恢复保留期、素材索引移除、来源重定位、完整备份恢复等细节尚未确认。单一结果 XML 不默认承担全部数据库备份职责。

需验收的可靠性包括：人工判断与集合修改在重跑/重启后保留；来源离线不被当作删除；缓存清理不损坏记录；部分失败可定位且不计作成功；新增成员不能抹掉旧审阅记录。源身份、校验、并发写入、恢复和模型缓存等技术契约需补齐。

## 13 验证与下一步

### 首轮场景验收清单

| 场景 | 必须看到的结果 |
|---|---|
| 多卡任务，模型尚未就绪 | 先有 Preview；用户可标记，分析逐步补充 |
| 坏天气整组 AI Reject | Collection 及全部候选仍可达，允许人工留 0 或多张 |
| 同图出现在三个集合 | Flag/Star 一致，组完成状态独立 |
| 人工拆组后换模型重跑 | 人工整理仍在，新分组是建议 |
| 已完成组追加素材 | 新增待审，历史进度保留 |
| 导出关闭复制 | 只生成一个 XML，不复制原片 |
| 视频无法解码 | 条目仍在，说明状态并可外部打开 |
| 来源离线、分析中断 | 记录与可用预览保留；重连/恢复后继续 |
| 删除并恢复 Collection | 素材和全局判断不丢，集合可恢复 |
| 清理缓存 | 整理记录不受影响，原片可用时重建 |

这是待执行的验收要求，不是已通过结果。规模、吞吐、交互延迟、分组质量与遗漏改善需真实测量。此前 [实验计划](04-MVP验证与研究计划.md) 中的数字门槛仍为提案。

### 建议后续顺序

1. 用创建任务、渐进 Preview、Collection blocks、Review 四个关键页面做可点击原型，补齐控件和状态细节。
2. 用坏天气遗漏、追加卡、跨集合改判、离线等案例走查；优先解决下面的未决事项。
3. 核对 BioScan 与本地历史 PhotoOS 的复用边界，制定 SQLite、任务服务、模型适配和 XML 交换契约；不预设重写或合仓。
4. 做小样本风险验证，再安排可执行的实施阶段和 500GB 验收。原型不等于已接通真实扫描服务。

### 实施前仍需决定

- 首个平台、实际 RAW/视频格式、CLI/MCP 首版范围。
- XML schema 与 Lightroom 交接路线、导出范围/去重/文件冲突和校验。
- Collection 默认分组、层级、排序及 block 摘要字段。
- 素材已审操作、任务级 Review 分母、零选与全局 Pick 冲突的具体交互。
- 能力版本/标签迁移和 Smart Collection 动态成员更新的精确规则。
- 来源重定位、SQLite 备份恢复、缓存预算、删除集合恢复期限。
- 具体模型、硬件预算、预览输入分辨率、队列恢复与依赖策略。

这些事项不阻止页面原型，但不可在实现时静默假定已获确认。指定的旧 Design Spec 原文仍未找到；旧规格仅作参考，不覆盖当前决定。
