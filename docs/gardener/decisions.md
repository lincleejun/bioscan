## 当前结论

Gardener 应先成为旅行与野生动物摄影的本地 Review 工作台：保留整次拍摄的候选，帮助用户按地点、事件和物种做选择，再把确认的结果交给 Lightroom。第一阶段的关键价值是减少遗漏和反复检查，同时降低筛片时间。模型分数、选中张数和“安全入库”都不能单独代表成功。

最值得验证的差异化是 **Coverage Review 与可追溯的人机决策闭环**。这仍是产品假设，不是已证实的市场独占能力。local-first、Collection、星标、AI 筛片分别已有成熟竞品。

| D28 | 任务支持边处理边 Review、暂停继续、中断恢复、失败项单独重试和来源离线恢复 | 用户确认；分阶段进度，保留有效结果和人工判断，新增结果不突然打乱当前浏览，结束显示完整/失败/未运行汇总 |

| D32 | 首版主导航为任务、Collections、全部素材、管理设置；任务内有 Preview 与 Collections 两个主要视图 | 用户确认；两视图共享素材及人工标记、随时切换、任务进度持续可见。进入集合 Review，导出从 Collection 或筛选结果发起，不单列主导航 |
| D33 | 分析完成与人工 Review 完成独立，用户明确确认 Collection 审阅完成 | 用户确认；滚动经过不算已审，不强迫逐张 Flag/Star。“完成本组”保留未标记状态并显示未逐张处理数量；“本组不留”明确零选，已有 Pick 冲突显式处理。新增素材提示新增待审并保留历史完成记录 |

| D35 | 首版支持多个独立任务、后台扫描队列、自由切换与历史续审；扫描状态和 Review 进度分别显示 | 用户已确认；默认顺序执行重型扫描，前一任务执行结束后继续下一任务，人工 Review 不占扫描名额。可扫描 B 同时 Review A；多任务同时跑重型 AI 后置。任务各有来源、描述、配置和结果；追加/重扫记录新一轮执行，不覆盖历史，具体调度与异常策略仍待细化 |
